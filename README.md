# 🔗 Backlink Checker

Внутренний инструмент 101RTP для проверки гест-постов: находит на странице донора ссылки на наши домены, определяет тип ссылки и анкор, проверяет индексацию страницы в Google.

**Продакшн:** https://backlink-checker.up.railway.app (вход не требуется)

---

## Что умеет

- Проверяет наличие ссылок сразу на несколько доменов (по умолчанию `101rtp.com` и `101rtp.net`)
- Показывает **анкор** и **тип ссылки**: dofollow / nofollow / sponsored / ugc
- Проверяет **индексацию в Google** через DataForSEO (`site:` запрос) с **кэшем** результатов
- Обходит антибот-защиту (Cloudflare) повторным запросом с TLS-отпечатком Chrome
- Результаты появляются в реальном времени (WebSocket)
- Хранит **историю** всех проверок в Postgres
- Экспорт в **CSV**
- «Перепроверить без ссылки» — повтор только для URL, где ссылка не найдена (индексация не перепроверяется)
- «Перепроверить ошибки» — повтор для URL с ошибкой индексации
- REST-эндпоинт для Google Sheets (Apps Script)

## Статусы ссылки

| Бейдж | Значение |
|---|---|
| ✓ Найдена | Ссылка на один из доменов найдена в HTML |
| ✗ Нет | Страница открылась, ссылки нет |
| ✗ 404 | Страница не существует — проверить URL |
| ⊘ Нет домена | Домен не существует (DNS) — проверить адрес |
| ⊘ Заблокирован | Сайт режет проверку даже после обхода — открыть вручную |
| ⊘ Таймаут | Сайт не ответил за 20 секунд |
| ⚠ JS-рендеринг | Ссылка, возможно, подгружается скриптом — проверить вручную |
| ⚠ Ошибка | Прочая техническая ошибка (текст — в колонке «Анкор») |

## Статусы индексации

| Бейдж | Значение |
|---|---|
| ✓ В индексе | Страница найдена в Google по `site:url` |
| ✗ Не в индексе | Страница не найдена |
| пометка «кэш» | Результат взят из кэша, DataForSEO не вызывался (дата — во всплывающей подсказке) |
| ⚠ DFS: нет баланса | Закончился баланс DataForSEO |
| ⚠ Неверные credentials | Неверный `DFS_CREDENTIALS` |

## Как проверяется ссылка

1. Прямой запрос (httpx, браузерный User-Agent).
2. Если ответ 401/403/429/503/52x/999 или таймаут — повтор через `curl_cffi` с отпечатком Chrome, затем Safari.
3. 404/410 и несуществующий домен — окончательный ответ, повторов нет.
4. HTML разбирается BeautifulSoup: ищутся все `<a href>`, у которых хост или URL содержит один из доменов.

## Как проверяется индексация

1. Ключ URL нормализуется: без схемы, `www.` и завершающего слэша.
2. Если в таблице `index_cache` есть свежий результат — он возвращается без вызова DataForSEO.
3. Иначе — DataForSEO SERP Live (`site:<url>`, location 2840, depth 10). При временной ошибке (5xx, Internal SE Server Error, таймаут) — одна повторная попытка через 2 секунды.
4. Успешный результат пишется в кэш. Ошибки не кэшируются.

TTL кэша: «в индексе» — 14 дней, «не в индексе» — 48 часов.

## Стек

- **Backend:** Python 3.11, FastAPI, httpx, curl_cffi, BeautifulSoup4
- **Frontend:** vanilla HTML/CSS/JS внутри `main.py`
- **База:** Postgres (Railway); SQLite как fallback, если `DATABASE_URL` не задан
- **Индексация:** DataForSEO SERP API
- **Деплой:** Railway (Dockerfile), автодеплой при пуше в `main`

## Переменные окружения

| Переменная | Обязательна | Описание |
|---|---|---|
| `DFS_CREDENTIALS` | да | Base64 от `login:api_password` DataForSEO ([API Access](https://app.dataforseo.com/api-access)). Получить: `echo -n 'login:password' \| base64` |
| `DATABASE_URL` | да (прод) | В Railway: `${{Postgres.DATABASE_URL}}`. Без неё — SQLite `/data/history.db` |
| `INDEX_CACHE_TTL_POSITIVE_HOURS` | нет | TTL для «в индексе», по умолчанию 336 (14 дней) |
| `INDEX_CACHE_TTL_NEGATIVE_HOURS` | нет | TTL для «не в индексе», по умолчанию 48 |

При первом старте на пустом Postgres история из `/data/history.db` (Railway Volume) переносится автоматически.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | Интерфейс |
| WS | `/ws/check` | Пакетная проверка: `{urls, target_domains, skip_indexation?}` → события `start` / `progress` / `done` / `error` |
| POST | `/api/check-single` | Одна ссылка для Apps Script: `{url, target_domains}` → `{exists, indexed, dofollow, anchor, link_url}` |
| GET | `/history` | Последние 100 прогонов |
| GET | `/history/{id}` | Результаты прогона |
| GET | `/health` | `{"status":"ok","db":"postgres"}` |

Прогоны из интерфейса сохраняются в историю. Вызовы `/api/check-single` в историю не пишутся, но используют кэш индексации.

## Google Apps Script

Скрипт `google-apps-script.js` проверяет гест-посты прямо из таблицы.

Читает лист **Guestposting**, строки, где **K** = `Published` и **L** содержит URL. Заполняет:

| Колонка | Значение |
|---|---|
| **M — Exists** | `Yes` / `No` / `404` / `Other` (подсветка: зелёный / красный / жёлтый) |
| **N — Index** | `Yes` / `No` / `Error` |
| **O — Dofollow** | `Yes` / `No` |

Анкор в таблицу не пишется (решение от 12.06.2026).

Домены: `101rtp.com`, `101rtp.net`, `101rtp.nz`, `101-rtp.nz` (константа `TARGET_DOMAINS`).

Установка: таблица → **Расширения → Apps Script** → вставить код → сохранить → перезагрузить таблицу. Появится меню **🔗 Backlink Checker**: «Проверить все Published» и «Проверить выделенные строки».

## Стоимость

Проверка ссылки — бесплатно. Проверка индексации — один платный SERP-запрос DataForSEO на URL (актуальная цена — в тарифах DataForSEO). Повторные проверки в пределах TTL кэша бесплатны.
